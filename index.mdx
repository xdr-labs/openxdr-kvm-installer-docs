# OpenXDR KVM Installer

## Documentation Overview

This site provides operator-focused documentation for **OpenXDR KVM Installer**, a **script-based automation framework for deploying and operating Stellar Cyber OpenXDR components in KVM-based Linux environments**.

OpenXDR KVM Installer automates host-side work required to deploy Stellar Cyber OpenXDR components on KVM. Instead of manually configuring libvirt, storage, networking, VM images, passthrough, CPU placement, and reboot state, it provides `whiptail`-based workflows, persistent state, and validation.

The installer is designed to **standardize and automate** common deployment tasks and reduce operational complexity:

- prepare KVM / libvirt host environments
- deploy Data Processor (DP) and Sensor virtual machines
- configure network interfaces, bridges, and PCI passthrough
- support Auto Execute or step-by-step execution
- validate host configuration and deployment state

All installation workflows use an **interactive menu-driven interface**, allowing operators to run only the required steps or execute an end-to-end deployment.

## Design Principles

### ① Repeatability

- installation steps are deterministic
- steps can be re-executed safely
- PoC, staging, and production environments can follow the same workflow

### ② Operational Transparency

- actions are visible through logs and validation
- operators can see what the automation is doing

### ③ Selective Automation

- run the complete automated deployment
- or execute only specific steps for the current scenario

### ④ Field-Driven Design

- workflows are based on real deployment and operational requirements rather than only lab assumptions

## Scope and Coverage

This documentation covers the lifecycle of deploying Stellar Cyber OpenXDR components on KVM hosts.

Included:

- host preparation and baseline configuration
- VM deployment and resource allocation
- networking and PCI passthrough
- post-deployment validation and health checks

Primary target environments:

- **on-premises**
- **KVM-based Linux**
- **Ubuntu LTS** as the primary documented platform

## Automation Scope

| Area | Automation |
| --- | --- |
| Hardware | Detect CPU, memory, disks, NICs, virtualization, and IOMMU |
| KVM Stack | Install and configure KVM/libvirt |
| Networking | Management, NAT/bridge, SR-IOV, SPAN, passthrough |
| Storage | Prepare LVM-based VM storage |
| VM Deployment | Prepare images, define VMs, and deploy components |
| Performance | CPU affinity, NUMA-aware placement, PCI passthrough |
| Lifecycle | Step state, reboot, resume |
| Safety | DRY_RUN, explicit confirmation, full configuration validation |

## What This Installer Does

- automates repetitive and error-prone deployment tasks
- enforces a consistent installation order and dependency handling
- supports both step-level execution and continuous Auto Execute
- validates system readiness and configuration correctness
- supports recovery and continuation from partially completed installations

## What This Installer Does Not Do

- replace official product documentation or architecture decisions
- automatically tune performance beyond documented best practices
- completely abstract Linux or KVM operational knowledge
- act as a general-purpose VM management platform

<Warning>
Basic familiarity with **Linux, KVM, and networking** is still required.
</Warning>

## Common Operational Flow

```text
Check hardware
  → Configure installer inputs with DRY_RUN enabled
  → Review the complete DRY_RUN flow
  → Run Full Configuration Validation
  → Resolve FAIL results and re-check inputs
  → Set DRY_RUN=0
  → Run all steps or a specific step
  → Reboot when required
  → Relaunch the same installer and resume
  → Perform post-deployment validation
```

<Warning>
The installer can modify networking, storage, kernel settings, virtualization configuration, and VM definitions. Always complete DRY_RUN and Full Configuration Validation before real execution.
</Warning>
