# Requirements

Exact resource sizing depends on the selected OpenXDR component and actual workload. Before production deployment, validate both Stellar sizing and the current installer configuration.

<Note>
The installation procedures and screenshots in this documentation are based on **Ubuntu Server 24.04 LTS**. The source installers may retain compatibility paths for some older Ubuntu/DP releases. For legacy deployment, verify the current source and the support scope of the target OpenXDR release separately.
</Note>

## Common Requirements

- Ubuntu Server supported by the selected installer
- Root privileges for system-changing operations
- Intel VT-x or AMD-V enabled in BIOS
- Intel VT-d or AMD-Vi when SR-IOV/PCI passthrough is used
- `whiptail`
- sufficient CPU, memory, and local storage for the target VMs
- host management connectivity
- additional SPAN/data interfaces for Sensor deployments
- network access required to download packages and Stellar component images
- a recovery plan before network/storage changes

## OS Baseline

The operational procedures in this documentation use **Ubuntu Server 24.04 LTS** as the baseline.

The current source may contain compatibility code for older Ubuntu or historical DP releases, but do not assume that the 24.04 procedure applies unchanged. For legacy deployments, compare the current installer source, target OpenXDR version, and Stellar support criteria.

## Product-Specific Sizing

Do not use this common page as the sizing source for a deployment. Each installer guide is self-contained and carries its own hardware baseline:

- **[DP KVM Installer](/installers/dp)** — DL/DA VM defaults, Data Lake, Management/Cluster NIC requirements
- **[Sensor KVM Installer](/installers/sensor)** — Sensor CPU, memory, storage, Management/SPAN requirements
- **[AIO & Sensor KVM Installer](/installers/aio-sensor)** — integrated AIO/Sensor sizing and Data Lake/SPAN requirements

The repository's generic 12 vCPU / 16 GB / 100 GB baseline is only a starting point for some Sensor/AIO installer checks and must not be treated as production sizing.

<Warning>
NIC renaming, the ifupdown transition, and disk provisioning can disrupt remote access or existing data. Secure console or out-of-band access first.
</Warning>
