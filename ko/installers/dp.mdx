# DP KVM Installer 사용자 가이드

![OpenXDR KVM Installer 전체 설치 흐름 개요](/images/DP-Installer/1.png)

## 개요

이 페이지는 **DP 설치를 처음부터 필수 초기 설정 완료까지 끝낼 수 있는 독립형 Runbook**입니다. DP 전용 하드웨어 기준, KVM 설치, Reboot/Resume, VM 배포, DL/DA 초기 설정까지 모두 포함합니다.

문서 기준 OS는 Ubuntu Server 24.04 LTS입니다. 설치 후 Appliance 설정만 빠르게 다시 확인하려면 **[DP Cluster 초기 구성](/ko/installers/dp-cluster-initial-configuration)**을 사용할 수 있습니다.

</Note>

### 아키텍처 개요

Stellar Cyber OpenXDR Platform은 KVM 가상화를 사용하여 단일 물리 서버에 배포됩니다.

설치 프로그램은 다음 구성 요소를 자동으로 생성하고 구성합니다.

- Ubuntu 24.04 기반 KVM 호스트
- libvirt / qemu-kvm 가상화 계층
- DLm (Data Lake Master) 가상 머신
- DAm (Data Analyzer Master) 가상 머신
- Linux 브리지 및 SR-IOV 기반 고성능 네트워킹
- 시스템 및 데이터 워크로드를 위한 전용 스토리지 볼륨

설치 프로그램은 다음 항목을 자동화하여 수동 설정을 제거하도록 설계되었습니다.

- 호스트 OS 준비 및 튜닝
- 네트워크 토폴로지 생성
- 스토리지 레이아웃 구성
- 가상 머신 라이프사이클 관리
- CPU affinity 및 SR-IOV 연결과 같은 성능 최적화

## 2. 설치 전 준비 사항 (필수 준비 단계)

### 시스템 요구사항

설치 프로그램을 실행하기 전에 다음 조건을 반드시 충족해야 합니다.

- **root 권한이 필요함**

설치 프로그램은 다음과 같은 저수준 시스템 작업을 수행합니다.

- 네트워크 재구성
- 커널 및 시스템 튜닝
- 디스크 및 파일 시스템 설정
- 가상 머신 생성 및 수정

### 문서 기준 운영체제

- 이 한국어 가이드는 **Ubuntu Server 24.04 LTS** 기준입니다.
- 현재 `DP-Installer.sh`에는 과거 DP/Ubuntu 릴리스용 호환 경로도 존재하므로 Legacy 배포 시에는 Source와 대상 릴리스 지원 범위를 별도로 확인하십시오.

### 준비 단계

설치 프로그램을 준비하기 위해 다음 단계를 수행합니다.

1. root 쉘로 전환합니다.

```bash
sudo -i
```

2. 현재 디렉터리에 설치 스크립트를 다운로드합니다.

```bash
curl -O https://raw.githubusercontent.com/xdr-labs/OpenXDR-KVM-Installer/main/DP-Installer.sh
```

3. 실행 권한을 부여합니다.

```bash
chmod +x DP-Installer.sh
```

4. 설치 프로그램을 실행합니다.

```bash
./DP-Installer.sh
```

### Management NIC

Management NIC은 다음 용도로 사용됩니다.

- KVM 호스트에 대한 원격 접속
- DLm 및 DAm 웹 인터페이스 접근
- 외부 관리 및 데이터 트래픽 처리

대규모 DP 배포 환경에서는 충분한 처리량을 확보하기 위해 **10GbE 인터페이스 사용을 권장**합니다.

### Cluster NIC

Cluster NIC은 DP 클러스터 내부 통신 전용입니다.

이 NIC은 SR-IOV를 사용하여 가상 스위치 계층을 우회한 상태로 VM에 직접 연결되어 최대 성능을 제공합니다.

요구사항:

- SR-IOV를 지원하는 NIC
- 10GbE 이상
- 일반적으로 Intel X710 또는 E810 시리즈

### Host Access NIC

Host Access NIC은 로컬 전용 유지보수 및 문제 해결을 목적으로 사용됩니다.

특징:

- 기본 IP 주소: `192.168.0.100`
- 원격 네트워크에서는 접근 불가
- 현장 접속, 긴급 복구, KVM 문제 해결에 사용

이 NIC은 특히 Management NIC이 10GbE로 구성되어 노트북에서 직접 접근할 수 없는 경우 매우 중요합니다.

### NIC 준비 및 설계 가이드라인

설치 중 NIC 선택을 단순화하기 위해, 설치 프로그램 실행 전에 필요한 NIC를 물리적으로 연결하는 것을 강력히 권장합니다.

설치 프로그램은 **링크 상태를 기준으로 인터페이스를 식별**하므로, 케이블이 연결되어 있으면 각 NIC의 역할을 명확히 구분할 수 있습니다.

![Management NIC 선택 화면](/images/DP-Installer/4.png)

## 3. 설치 프로그램 탐색

설치 프로그램은 Whiptail로 구현된 대화형 메뉴 기반 인터페이스를 제공합니다.

### 탐색 방법 안내

- **Spacebar 또는 아래 화살표(↓)**: 메뉴 항목 이동
- **Enter**: 선택
- **q 또는 ESC**: 도움말 화면 종료 또는 이전 메뉴로 이동

### 상태 인식 실행 방식

설치 프로그램은 상태 인식(state-aware) 방식으로 동작합니다.

설치 상태는 다음 경로에 저장됩니다.

```text
/root/xdr-installer
```

- 완료된 단계는 기록됨
- 재부팅 또는 중단 후, 다음 미완료 단계부터 자동 재개됨

모든 설치 상태를 초기화하고 처음부터 다시 시작하려면 다음 명령을 실행합니다.

```bash
rm -rf /root/xdr-installer
```

### 필수 재부팅 단계

설치 프로그램은 다음 단계 이후 자동으로 시스템 재부팅을 수행합니다.

- **STEP 03 – Network conversion (netplan → ifupdown)**
- **STEP 05 – Kernel and system-level tuning**

이 재부팅은 필수 사항이며 생략할 수 없습니다.

재부팅 이후:

1. 서버에 다시 로그인
2. 설치 프로그램 재실행
3. **Menu 1** 선택

설치 프로그램은 자동으로 이어서 실행됩니다.

### 메인 메뉴 옵션 개요

#### 1. Auto Execute All Steps

- 다음 미완료 단계부터 모든 단계를 자동으로 실행
- 재부팅 후 마지막 완료 단계부터 자동으로 재개
- 권장 용도
  - 초기 설치
  - 재부팅 후 이어서 진행

#### 2. Select and Run Specific Step Only

- 개별 단계를 독립적으로 실행
- 권장 용도
  - DP VM 재배포
  - 네트워크 변경
  - 이미지 업데이트
  - 스토리지 재구성

#### 3. Configuration

설치 파라미터를 구성합니다.

- `DRY_RUN` (default: `1`)
- `DP_VERSION`
- `MGT_NIC`
- `CLTR0_NIC`
- `DATA_SSD_LIST`
- `CLUSTER_NIC_TYPE`
- ACPS credentials
  - username
  - password
  - URL

#### 4. Full Configuration Validation

전체 시스템 구성을 검증합니다.

검사 항목:

- KVM
- DP VM
- 네트워크
- SR-IOV
- 스토리지

상세 로그와 함께 오류 및 경고를 표시합니다.

#### 5. Script Usage Guide

- 내장 도움말 가이드 표시

#### 6. View Log

- 설치 로그 파일 표시

#### 7. Exit

- 설치 프로그램 종료

## 4. 설치 시나리오

설치 프로그램은 다음 두 가지 환경을 모두 지원합니다.

- 신규 설치
- 부분적으로 구성된 시스템

설치 프로그램은 상태 인식 방식으로 동작하므로, 완료된 단계는 기록되며 재부팅 후에도 안전하게 이어서 실행할 수 있습니다.

### 4.1 신규 설치 (초기 배포)

이 시나리오는 Ubuntu 설치 직후 설치 프로그램을 실행하는 경우에 해당합니다.

#### 초기 설정

메인 메뉴에서 다음을 선택합니다.

```text
3) Configuration
```

![DP Installer Configuration 화면](/images/DP-Installer/5.png)

다음 항목을 설정합니다.

- **DRY_RUN**
  - 기본값은 `1` (시뮬레이션 모드)
  - 실제 설치를 수행하려면 `0`으로 변경
- **DP Version**
  - 배포할 Data Platform 버전 지정
- **ACPS Account / Password**
  - DP QCOW2 이미지 및 배포 파일 다운로드에 필요
- **ACPS URL**
  - 운영 환경에서는 기본값 유지
  - 개발 또는 POC 환경에서만 변경

설정 완료 후 메인 메뉴로 돌아갑니다.

#### 자동 실행

다음 메뉴를 선택합니다.

```text
1) Auto execute all steps
```

![DP Installer Auto Execute All Steps 화면](/images/DP-Installer/6.png)

설치 프로그램은 다음 단계를 순차적으로 실행합니다.

```text
STEP 01 → STEP 02 → STEP 03 → … → STEP 14
```

#### 필수 재부팅 단계

**STEP 03**

- 네트워크 설정을 netplan에서 ifupdown으로 변환
- 변경 사항 적용을 위해 재부팅 필요

**STEP 05**

- 커널 및 시스템 수준 변경 적용
- 시스템 안정성을 위해 재부팅 필요

#### 재부팅 이후

시스템이 재시작되면 다음을 수행합니다.

1. 서버에 다시 로그인
2. 설치 프로그램 재실행
3. **Menu 1** 선택

설치 프로그램은 다음 미완료 단계부터 자동으로 재개됩니다.

### 4.2 개별 단계 실행 (특정 단계만 실행)

이 모드는 전체 설치 흐름을 실행하지 않고 단일 설치 단계만 실행할 수 있도록 합니다.

운영 유연성을 위해 설계되었으며 다음과 같은 상황에서 주로 사용됩니다.

- 특정 설정만 변경해야 하는 경우
- 이전에 실패한 단계를 다시 실행해야 하는 경우
- 특정 구성 요소를 재배포 또는 재구성해야 하는 경우

선택한 단계만 실행되며, 이미 완료된 다른 단계는 변경되지 않습니다.

#### 대표적인 사용 사례

- DLm / DAm 가상 머신 재배포
- DP 이미지 또는 배포 파일 재다운로드
- SR-IOV 인터페이스 재구성 또는 재연결
- CPU affinity 및 성능 튜닝 재적용

#### 개별 단계 실행 방법

메인 메뉴에서 다음을 선택합니다.

```text
2) Select and run specific step only
```

![DP Installer 개별 Step 선택 화면](/images/DP-Installer/7.png)

개별 Step 선택 화면에는 다음 단계가 표시됩니다.

| Step | 작업 |
| ---: | --- |
| 01 | Detect and select hardware / NIC / disks |
| 02 | Install HWE kernel |
| 03 | Rename NICs / switch to ifupdown and configure networking |
| 04 | Install and configure KVM / libvirt |
| 05 | Tune kernel parameters / KSM / swap |
| 06 | Configure SR-IOV drivers + NTPsec |
| 07 | LVM storage (DL/DA root + data) |
| 08 | libvirt hooks and OOM recovery scripts |
| 09 | Download DP image and deployment scripts |
| 10 | Deploy DL-master VM |
| 11 | Deploy DA-master VM |
| 12 | SR-IOV / CPU Affinity / PCI Passthrough |
| 13 | Install DP Appliance CLI package |
| 14 | Configure NFS backup server (DP configuration backup only) |

실행 절차:

1. 실행할 단계 선택
2. 실행 확인
3. 해당 단계만 실행된 후 메뉴로 복귀

이 방식은 관련 없는 구성 요소에 불필요한 변경을 피함으로써 위험을 최소화합니다.

#### STEP 14 — NFS 백업 서버 구성

현재 DP Installer의 마지막 단계는 **DP configuration backup용 NFS export**를 구성합니다. 이 단계는 Data Lake 데이터 백업이 아니라 DP 구성 백업을 위한 기능입니다.

기본 설정에는 `/stellarcyber` export 경로와 DL 내부 주소를 기준으로 한 허용 클라이언트 값이 포함되므로, 실제 환경에 맞는 값인지 Configuration에서 확인한 뒤 적용하십시오.

#### 중요 참고 사항

- 일부 단계는 이전 단계에 의존함
  - 예: CPU affinity 설정은 VM이 이미 존재해야 함
- 필수 조건이 충족되지 않아 단계가 실패하면, 먼저 필요한 이전 단계를 다시 실행
- 문제 해결 시 항상 가장 작은 관련 단계부터 실행할 것

## 6. 설치 후 일반적인 변경 사항

### 자동 재부팅 알림

- **STEP 03은 항상 시스템 재부팅을 발생시킵니다.**

### 변경 시나리오

#### Management 또는 Host Access NIC / IP 변경

다음 단계를 재실행합니다.


## 8. 하드웨어 및 소프트웨어 요구사항

실제 실행 전에 이 페이지에서 다음 DP 전용 요구사항을 모두 확인하십시오.

- 문서 기준 Ubuntu Server 24.04 LTS
- root 권한
- CPU Hardware Virtualization 활성화
- SR-IOV/Direct Device 사용 시 VT-d / IOMMU 활성화
- 위 표의 현재 DL/DA VM 기본값을 수용할 CPU와 Memory
- 선택한 설계에 필요한 OS/VM Storage와 전용 Data Lake Disk
- Management NIC, Cluster NIC, 장애 복구용 Host Access 연결
- Package, Image, Deployment Artifact 다운로드용 Network Access

**[Ubuntu 24.04 설치 가이드](/ko/getting-started/installing-ubuntu-24-04)**는 추가 참고용이며, DP 하드웨어 선택에 필요한 제품별 요구사항은 이 페이지에 모두 요약되어 있습니다.

## 9. BIOS 및 플랫폼 설정

다음 기능이 플랫폼 요구사항에 맞게 구성되어 있는지 확인하십시오.

- Intel Virtualization Technology
- VT-d / IOMMU
- 클러스터 NIC의 SR-IOV 기능

<Warning>
DP Cluster Interface에 **SR-IOV**를 사용하는 경우 서버 BIOS와 NIC 장치 설정을 모두 확인하십시오. Dell/Intel X710·E810 계열의 일반적인 가이드는 **Global/System SR-IOV 활성화 + NIC Device Level Virtualization Mode의 SR-IOV 활성화**를 요구합니다. 정확한 메뉴와 요구사항은 서버/NIC 펌웨어 버전에 따라 달라질 수 있으므로 제조사 문서와 [Ubuntu 24.04 설치 가이드](/ko/getting-started/installing-ubuntu-24-04)를 함께 확인하십시오.
</Warning>

## 10. 필수 DP 초기 구성

VM이 실행 중인 것만으로 DP 설치가 완료된 것은 아닙니다. 운영 전 다음 DL/DA 설정을 완료하십시오.

<Note>
KVM Host별 NAT Management Network는 고정입니다. DL은 `192.168.122.2/24`, DA는 `192.168.122.3/24`, Gateway는 `192.168.122.1`, DNS는 `8.8.8.8`을 사용합니다. 각 물리 KVM Host는 독립적인 libvirt NAT Network를 사용하므로 서로 다른 Host에서 같은 NAT 주소를 재사용할 수 있습니다.
</Note>

### 10.1 DL Master

```text
set interface management ip 192.168.122.2/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8
set hostname dl-master
reboot
```

재접속 후:

```text
set role DL-master
set cluster_name dl-master
set cluster_size 1
show interface all
```

`show interface all` 결과에서 실제 Cluster NIC를 확인한 뒤:

```text
set cluster_interface <cluster-interface>
set interface cluster ip 192.168.12.25/24
set cm 192.168.12.25
set mode MDS enable
set mode replica security
set mode shard_balance enable
set otp <YOUR-OTP>
reset
```

Storage 추가:

```text
show storage
add storage blk vdb
```

<Warning>
`add storage blk`는 선택한 Device를 Format합니다. 반드시 `vdb`를 확인하십시오. 실제 OTP는 문서나 Git 저장소에 저장하지 마십시오.
</Warning>

### 10.2 DL Worker

Worker 1 예시:

```text
set interface management ip 192.168.122.2/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8
set hostname dl-worker1
reboot
```

재접속 후:

```text
set role resource
show interface all
set cluster_interface <cluster-interface>
set interface cluster ip 192.168.12.26/24
set cm 192.168.12.25
reset
show storage
add storage blk vdb
```

추가 Worker는 `dl-worker2 / 192.168.12.27/24`처럼 고유 값을 사용합니다.

### 10.3 DA Master / Worker

DA Master 예시:

```text
set interface management ip 192.168.122.3/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8
set hostname da-master
reboot
```

재접속 후:

```text
set role resource
show interface all
set cluster_interface <cluster-interface>
set interface cluster ip 192.168.12.50/24
set cm 192.168.12.25
reset
```

DA Worker는 `da-worker1 / 192.168.12.51/24`처럼 고유 값을 사용합니다.

### 10.4 DA Resource를 DA-Master로 전환

DL Master가 **System Ready**이고 대상 DA Master가 `resource`이면:

1. Data Platform GUI에 접속합니다.
2. **System → DATA MANAGEMENT → Resources**에서 DA Resource가 Ready인지 확인합니다.
3. **System → DATA MANAGEMENT → Data Analyzer**로 이동합니다.
4. Data Analyzer Cluster를 생성합니다.
5. DA Resource를 선택하고 **Role in Cluster = DA-Master**로 설정합니다.
6. Submit 후 Node가 Healthy 상태인지 확인합니다.

### 10.5 Receiver 및 Sensor Profile

1. **System → DATA SOURCE MANAGEMENT → Receivers**로 이동합니다.
2. **Receiver Hostname**이 DL-Master가 아니라 **DA-Master**를 가리키는지 확인합니다.
3. 최소 하나의 Sensor Profile이 해당 Receiver를 사용하도록 설정되어 있는지 확인합니다.
4. `show logforwarder`에 출력이 없으면 Receiver Hostname부터 확인합니다.

### 10.6 DP 최종 체크리스트

- DL/DA VM이 실행 중이고 Autostart가 활성화되어 있음
- DL Management IP = `192.168.122.2/24`
- DA Management IP = `192.168.122.3/24`
- 모든 Cluster Node가 고유한 Hostname과 Cluster IP를 사용함
- `show interface all`에서 실제 Cluster Interface를 선택함
- 모든 Node의 CM이 DL Master Cluster IP를 가리킴. 이 문서 예시는 `192.168.12.25`
- 필요한 Node에 의도한 `vdb` Storage가 추가됨
- DA-Master가 Data Analyzer에서 Healthy 상태임
- Receiver Hostname이 DA-Master를 가리키고 Sensor Profile이 해당 Receiver를 사용함
- Full Configuration Validation에 미해결 FAIL이 없음

Installer 설명 없이 초기 설정 명령만 다시 보려면 **[DP Cluster 초기 구성](/ko/installers/dp-cluster-initial-configuration)**을 사용하십시오.
