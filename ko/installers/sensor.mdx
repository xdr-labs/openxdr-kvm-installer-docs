# Sensor KVM Installer 사용자 가이드

![OpenXDR KVM Sensor Installer 빠른 참조 가이드](/images/Sensor-Installer/1.png)

## 개요

이 페이지는 **Standalone Sensor 설치를 처음부터 Data Platform 연결 및 승인까지 끝낼 수 있는 독립형 Runbook**입니다. Sensor 전용 하드웨어 기준, NAT/Bridge, SPAN 연결, Installer 실행, CM 연결과 Authorization을 모두 포함합니다.

문서 기준 OS는 Ubuntu Server 24.04 LTS입니다.

## 1. 시스템 아키텍처

### 하드웨어 한눈에 보기

| 항목 | Sensor 요구사항 / 가이드 |
| --- | --- |
| CPU | 12 vCPU 이상, VM Sizing은 자동 계산 |
| Memory | 16 GB 이상, VM Sizing은 자동 계산 |
| Storage | Sensor Storage 생성 전 `ubuntu-vg`에 최소 100 GB Free Space |
| Management NIC | 1 GbE 이상 |
| SPAN NIC | Traffic 설계에 필요한 수량 |
| SPAN 연결 | PCI Passthrough, 제한 환경에서는 Bridge |
| BIOS | CPU Virtualization 활성화, PCI Passthrough 사용 시 VT-d/IOMMU 필요 |
| 검증된 Hardware | Dell PowerEdge R650 / R660 / R670 |
| OS | 문서 기준 Ubuntu Server 24.04 LTS |

<Note>
위 값은 프로젝트 시작 기준이며 모든 Production 환경의 보편적인 Sizing 기준은 아닙니다. Traffic Volume과 Workload에 따라 Resource를 늘리십시오.
</Note>

### 아키텍처 개요

Stellar Cyber XDR Sensor는 KVM 가상화를 사용하는 물리 서버 상에서 단일 가상 머신으로 배포됩니다.

설치 프로그램은 다음 구성 요소를 자동으로 설정합니다.

- Ubuntu 24.04 기반 KVM 호스트
- libvirt / qemu-kvm 가상화 계층
- XDR Sensor 가상 머신
- NAT 또는 L2 브리지 기반 Sensor 네트워크
- PCI 패스스루 기반 SPAN 트래픽 수집
- LVM 기반 전용 스토리지
- 커널 및 CPU 성능 튜닝

설치 프로그램은 다음 항목을 자동화하여 수동 개입을 최소화하도록 설계되었습니다.

- 호스트 OS 준비 및 성능 튜닝
- 네트워크 토폴로지 구성
- 스토리지 프로비저닝
- Sensor VM 라이프사이클 관리
- PCI 패스스루 기반 고속 패킷 수집

## 2. 설치 전 준비 사항 (필수 준비 단계)

### 시스템 요구사항

설치 프로그램 실행 전에 다음 조건을 반드시 충족해야 합니다.

- **root 권한이 필요함**
- 설치 프로그램은 다음과 같은 시스템 수준 작업을 수행합니다.
  - 네트워크 설정 변경
  - 커널 및 GRUB 설정 수정
  - 디스크 및 파일 시스템 구성
  - 가상 머신 생성 및 수정

### 문서 기준 운영체제

- 이 한국어 가이드는 **Ubuntu Server 24.04 LTS** 기준입니다.
- Source Installer에는 이전 Ubuntu 릴리스에 대한 호환 코드가 존재할 수 있으므로 Legacy 배포는 현재 Source와 대상 OpenXDR 릴리스 지원 범위를 별도로 확인하십시오.

### 준비 단계

1. root 쉘로 전환합니다.

```bash
sudo -i
```

2. 현재 디렉터리에 설치 스크립트를 다운로드합니다.

```bash
curl -O https://raw.githubusercontent.com/xdr-labs/OpenXDR-KVM-Installer/main/Sensor-Installer.sh
```

3. 실행 권한을 부여합니다.

```bash
chmod +x Sensor-Installer.sh
```

4. 설치 프로그램을 실행합니다.

```bash
./Sensor-Installer.sh
```

## 3. Sensor 네트워크 모드

설치 프로그램은 서로 다른 운영 요구사항을 충족하기 위해 두 가지 Sensor 네트워크 모드를 지원합니다.

### NAT 모드

- KVM 호스트와 Sensor VM이 하나의 외부 IP 주소를 공유
- libvirt 내부 NAT 네트워크(`virbr0`) 사용
- Sensor VM에 고정 내부 IP 할당
  - 기본값: `192.168.122.2`
- 다음 이유로 설치 및 관리 시 추가적인 주의가 필요함
  - 외부 접근이 간접적으로 이루어짐
  - 포트 포워딩 및 관리 트래픽 흐름을 고려해야 함

#### 대표적인 사용 사례

- Lab, POC 및 운영 환경
- 외부 노출이 제한된 단순한 배포 환경
- IP 자원이 제한된 환경

> 관리 인터페이스는 NAT 모드, SPAN NIC은 Bridge 모드로 구성할 수 있습니다.

![NAT 관리 인터페이스와 Bridge SPAN 구성 예시](/images/Sensor-Installer/2.png)

### 브리지 모드

- Sensor VM이 **전용 L2 브리지**를 통해 연결됨
- Sensor 트래픽이 KVM 호스트와 완전히 분리됨
- 고성능 물리 NIC 필요
- Appliance CLI는 Sensor 브리지에 ACL을 적용할 수 없음

#### 권장 사용 시나리오

- 고처리량 Sensor 배포가 필요한 경우
- 10GbE 이상의 인터페이스를 사용하는 환경
- 보안 정책상 호스트와 Sensor 인터페이스의 엄격한 분리가 필요한 경우
- 운영 환경에서 성능 민감 Sensor 노드를 배포하는 경우

> 관리 인터페이스는 Bridge 모드, SPAN NIC은 PCI 패스스루 모드로 구성할 수 있습니다.

![Bridge 관리 인터페이스와 PCI Passthrough SPAN 구성 예시](/images/Sensor-Installer/3.png)

## 4. SPAN 연결 방식

설치 프로그램은 배포 환경에 따라 두 가지 SPAN 연결 방식을 지원합니다.

### PCI 패스스루 (기본 방식)

- 물리 SPAN NIC을 Sensor VM에 직접 패스스루
- 최대 패킷 처리량과 최소 지연 시간 제공
- 가상 스위칭 계층을 완전히 우회

#### 주요 특징

- 표준 PCI 패스스루 방식만 사용
- BIOS에서 IOMMU 활성화 필요
- 대부분의 물리 환경에서 기본값이자 권장 방식

### 브리지 모드 (SPAN)

- SPAN 트래픽을 L2 브리지를 통해 연결
- 주로 다음 환경에서 사용됨
  - 프라이빗 클라우드 환경
  - 가상화 또는 중첩 가상화 환경
  - PCI 패스스루 사용이 제한된 환경

이 방식은 성능을 일부 희생하는 대신 유연성과 호환성을 제공합니다.

### NIC 준비 및 설계 가이드라인

설치 과정에서 NIC 선택을 단순화하기 위해 설치 프로그램 실행 전에 필요한 NIC를 물리적으로 연결하는 것을 강력히 권장합니다.

설치 프로그램은 링크 상태를 기준으로 인터페이스를 식별하므로, 케이블이 연결되어 있으면 각 NIC의 역할을 명확히 구분할 수 있습니다.

![Sensor SPAN NIC 선택 화면](/images/Sensor-Installer/4.png)

## 5. 설치 프로그램 탐색 및 실행 모델

### 메뉴 탐색 방법

설치 프로그램은 대화형 메뉴 기반 인터페이스를 제공합니다.

- **Spacebar / ↓** : 앞으로 스크롤
- **↑** : 뒤로 스크롤
- **q** : 도움말 또는 가이드 화면 종료

### 상태 인식 실행 방식

설치 프로그램의 실행 상태는 다음 경로에 저장됩니다.

```text
/root/xdr-installer
```

완료된 단계가 기록되며, 이를 통해 설치 프로그램은 다음을 수행할 수 있습니다.

- 재부팅 후 자동으로 이어서 실행
- 이미 완료된 단계 건너뛰기
- 선택한 단계의 안전한 재실행

모든 설치 상태를 초기화하려면 다음 명령을 실행합니다.

```bash
rm -rf /root/xdr-installer
```

### DRY-RUN 모드

- 기본값: `DRY_RUN=1`
- 모든 작업은 시뮬레이션으로만 수행
- 실제 시스템 변경은 적용되지 않음

실제 배포 전에 반드시 다음과 같이 설정해야 합니다.

```text
DRY_RUN=0
```

메뉴 **3) Configuration**에서 설정합니다.

## 9. Sensor 배포 이후

### 9.1 Management Network 설정

Standalone Sensor KVM Installer는 NAT와 Bridge 두 가지 Management Network 모드를 지원합니다.

#### NAT 모드

Sensor VM은 다음 KVM 고정 NAT 주소를 사용합니다.

- Sensor IP: `192.168.122.2/24`
- Gateway: `192.168.122.1`
- DNS: `8.8.8.8`

Sensor CLI에서 다음 값을 설정하거나 확인합니다.

```text
set interface management ip 192.168.122.2/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8
```

#### Bridge 모드

Bridge 모드에서는 Installer Configuration에서 지정한 Sensor Management IP, Netmask, Gateway 및 DNS를 사용합니다.

Bridge 모드 주소를 위의 NAT 값으로 변경하지 마십시오. 수동 수정이 필요한 경우 실제 환경에 할당한 값을 사용합니다.

```text
set interface management ip <SENSOR-IP>/<NETMASK>
set interface management gateway <GATEWAY>
set interface management dns <DNS>
```

현재 Management 설정을 확인합니다.

```text
show interfaces
```

<Warning>
Standalone Sensor Installer의 NAT Sensor는 `192.168.122.2`를 사용합니다. 반면 **AIO & Sensor 통합 Installer**에서는 `192.168.122.2`를 AIO가 사용하므로 Sensor는 `192.168.122.3`을 사용합니다. 통합 배포에서는 **[AIO & Sensor 초기 구성](/ko/installers/aio-sensor-initial-configuration)** 문서를 따르십시오.
</Warning>

### 9.2 로그인 및 기본 비밀번호 변경

Sensor Console에 접속하여 초기 계정으로 로그인합니다.

```text
aella / changeme
```


### 9.3 고유한 Sensor Hostname 설정

Hostname은 Stellar Cyber에 표시되므로 Sensor마다 고유한 이름을 사용해야 합니다.

```text
set hostname <SENSOR-HOSTNAME>
```

예:

```text
set hostname sensor-site1
```

### 9.4 Sensor를 Data Platform에 연결

`set cm`에는 Sensor가 접근할 수 있는 Stellar Cyber Platform Management Endpoint를 지정합니다.

Cluster Data Platform에서는 **DL-master Management Interface 주소**를 사용합니다. Single DP/AIO 환경에서는 **Platform Management IP 또는 Hostname**을 사용합니다.

예:

```text
set cm <DP-MANAGEMENT-IP>
```

또는:

```text
set cm <DP-HOSTNAME>
```

<Note>
Standalone Sensor Installer에서 `set cm`은 Sensor 자신의 NAT 주소인 `192.168.122.2`가 아닙니다. Sensor에서 접근 가능한 Stellar Cyber Platform의 Management 주소 또는 Hostname을 입력해야 합니다.
</Note>

연결 상태를 확인합니다.

```text
show cm
```

다음을 확인하십시오.

- **CM Controller**에 의도한 Data Platform 주소 또는 Hostname이 표시됨
- **Status**가 **Established**

연결이 정상적으로 Establish되면 다음 명령으로 종료합니다.

```text
quit
```

Sensor는 Stellar Cyber Platform에 자동으로 접속하여 자신을 등록합니다.

### 9.5 NTP 및 Timezone 구성

Stellar Cyber는 Sensor에서 NTP와 올바른 Timezone을 구성할 것을 강력히 권장합니다.

정확한 시간 동기화는 Event Timestamp, Correlation 및 문제 해결에 중요합니다.

지원되는 설정 절차는 [Stellar Cyber NTP 및 Timezone Best Practices](https://docs.stellarcyber.ai/6.5.x/Using/Guides/BestPractices-NTP.htm)를 참고하십시오.

### 9.6 Sensor 승인

Sensor가 Stellar Cyber Platform에 등록된 후 운영 데이터 수집에 사용하기 전에 Sensor를 승인해야 합니다.

자세한 절차는 [Stellar Cyber Sensor 승인 문서](https://docs.stellarcyber.ai/6.5.x/Configure/Sensors/Sensor-List-Main.htm#Sensor)를 참고하십시오.

<Warning>
등록은 되었지만 승인되지 않은 Sensor는 정상 운영 준비가 완료된 상태가 아닙니다.
</Warning>

## 10. 하드웨어 및 소프트웨어 요구사항

실제 실행 전에 다음을 확인하십시오.

- Ubuntu Server 24.04 LTS
- root 권한
- 프로젝트 시작 기준 CPU 12 vCPU 이상, Memory 16 GB 이상
- `ubuntu-vg`에 최소 100 GB Free Space
- Management NIC 및 필요한 SPAN/Data NIC
- CPU Virtualization 활성화
- PCI Passthrough 사용 시 VT-d/IOMMU 활성화
- Package 및 Sensor Image 다운로드용 Network Access
- Network 전환 전 Console 또는 Out-of-Band Access

Storage 확인:

```bash
df -h
vgs
lvs
```

**[Ubuntu 24.04 설치 가이드](/ko/getting-started/installing-ubuntu-24-04)**는 추가 참고용이며, Sensor 전용 Hardware Baseline은 이 페이지에 모두 요약되어 있습니다.

## 12. Sensor 최종 체크리스트

- Full Configuration Validation에 미해결 FAIL이 없음
- Sensor VM이 실행 중이고 Autostart가 활성화되어 있음
- NAT 모드는 `192.168.122.2/24`, Bridge 모드는 환경별 Management Address를 사용함
- `show interfaces`에 의도한 Management 설정이 표시됨
- Sensor Hostname이 고유함
- `set cm`이 Sensor 자신의 NAT IP가 아니라 접근 가능한 Data Platform Management 주소를 가리킴
- `show cm`의 **Status가 Established**
- NTP/Timezone이 구성됨
- Stellar Cyber에서 Sensor Authorization이 완료됨
- SPAN Interface가 의도한 PCI Passthrough 또는 Bridge 방식으로 연결됨
