# AIO & Sensor KVM Installer 사용자 가이드

![AIO & Sensor KVM Installer 전체 설치 흐름 개요](/images/AIO-Sensor/1.png)

## 개요

본 문서는 **Stellar Cyber OpenXDR AIO & Sensor KVM Installer**에 대한 종합 사용자 가이드입니다.

Ubuntu Server 24.04 LTS가 실행 중인 KVM 호스트에서 **All-in-One(AIO) OpenXDR 어플라이언스와 XDR Sensor 가상 머신을 설치, 구성, 검증 및 운영하는 방법**을 설명합니다.

본 가이드는 가상화 인프라 환경에서 OpenXDR 환경을 배포하고 관리하는 시스템 엔지니어 및 운영자를 대상으로 합니다.

이 문서는 다음과 같은 실제 운영 시나리오를 반영합니다.

- 초기 설치
- 부분 재구성
- 단계 재실행
- 재부팅 또는 중단 이후 복구

본 문서에 설명된 모든 절차는 설치 프로그램의 검증된 동작 방식을 따르며, 안정적이고 반복 가능하며 운영 환경에 적합한 배포를 보장하도록 설계되었습니다.

## 1. 시스템 아키텍처

### Dell R660 기반 예시 구성

![Dell R660 기반 AIO 및 Sensor KVM 아키텍처 예시](/images/AIO-Sensor/2.png)

예시 아키텍처 구성은 다음과 같습니다.

| 구성 요소 | 예시 값 |
| --- | --- |
| KVM Host | Dell R660 / Ubuntu 24.04 |
| AIO VM | 48 vCPU, 136 GB RAM |
| MDS VM | 44 vCPU, 80 GB RAM |
| Host Access | 1 GbE UTP, 로컬 전용 `192.168.0.100` |
| Management & Data Link | 1 GbE 또는 10 GbE |
| Sensor SPAN | PCI Passthrough |
| OS / VM Disk | 1 × 1.92 TB — Ubuntu 24.04, AIO VM, MDS VM |
| Data Lake | 6 × 3.84 TB — DLm 및 AIO용 |

### 아키텍처 개요

Stellar Cyber OpenXDR 플랫폼은 KVM 가상화를 사용하는 단일 물리 서버에 배포됩니다.

설치 프로그램은 다음 구성 요소를 자동으로 생성하고 구성합니다.

- Ubuntu 24.04 기반 KVM 호스트
- libvirt / qemu-kvm 가상화 계층
- AIO 가상 머신 (Data Platform + Analyzer 통합)
- Sensor 가상 머신(들)
- NAT 기반 가상 네트워크
- SPAN 트래픽을 위한 PCI Passthrough
- AIO 및 Sensor 워크로드를 위한 LVM 기반 스토리지
- CPU affinity 및 커널 수준 성능 튜닝

설치 프로그램은 다음 작업을 자동화하여 반복적인 수동 설정을 줄이도록 설계되었습니다.

- 호스트 OS 준비 및 튜닝
- 네트워크 구성 및 변환
- 스토리지 레이아웃 생성
- 가상 머신 라이프사이클 관리
- PCI Passthrough 및 CPU pinning과 같은 성능 중요 설정

- 네트워크 재구성
- 커널 및 시스템 튜닝
- 디스크 및 파일 시스템 설정
- 가상 머신 생성 및 수정

### 문서 기준 운영체제

- 이 한국어 가이드는 **Ubuntu Server 24.04 LTS** 기준입니다.
- Legacy Ubuntu/OpenXDR 조합은 현재 Source Installer와 대상 릴리스 지원 범위를 별도로 확인하십시오.

## 3. 준비 단계

설치 프로그램을 준비하기 위해 다음 단계를 수행합니다.

1. root 쉘로 전환합니다.

```bash
sudo -i
```

2. 현재 디렉터리에 설치 스크립트를 다운로드합니다.

```bash
curl -O https://raw.githubusercontent.com/xdr-labs/OpenXDR-KVM-Installer/main/AIO-Sensor-Installer.sh
```

3. 실행 권한을 부여합니다.

```bash
chmod +x AIO-Sensor-Installer.sh
```

4. 설치 프로그램을 실행합니다.

```bash
./AIO-Sensor-Installer.sh
```

## 4. NIC 준비 및 설계 가이드라인

### 관리 NIC

관리 NIC는 다음 용도로 사용됩니다.

- KVM 호스트에 대한 원격 접속
- AIO 웹 인터페이스 접근
- 외부 관리 트래픽 처리

### Sensor 네트워크 모드

- **NAT 모드만 지원**
- 기본 KVM `virbr0` 네트워크를 사용하여 구현됨
- 이 설계는 배포를 단순화하고 운영 리스크를 줄임

### SPAN 연결 방식

- **PCI Passthrough만 지원**
- 브리지 기반 SPAN 연결은 지원되지 않음
- BIOS에서 IOMMU 활성화 필요
- PCI Passthrough는 Sensor 워크로드에 대해 가장 높은 패킷 캡처 성능을 제공

### NIC 준비 및 설계 가이드라인

설치 중 NIC 선택을 단순화하기 위해, 설치 프로그램 실행 전에 필요한 NIC를 물리적으로 연결하는 것을 강력히 권장합니다.

설치 프로그램은 **링크 상태를 기준으로 인터페이스를 식별**하므로, 케이블이 연결되어 있으면 각 NIC의 역할을 명확히 구분할 수 있습니다.

![NAT uplink NIC 선택 화면](/images/AIO-Sensor/3.png)

## 9. AIO & Sensor 배포 이후

### 9.1 KVM 기본 네트워크 구성

KVM AIO 배포는 로컬 libvirt NAT Network를 사용하며 Guest 주소는 다음과 같이 고정됩니다.

- AIO IP: `192.168.122.2/24`
- MDS IP: `192.168.122.3/24`
- Gateway: `192.168.122.1`
- DNS: `8.8.8.8`

<Note>
AIO 구성에서는 AIO Management IP와 `set cm`에 동일한 IP를 사용합니다. 이 KVM 배포에서는 두 값 모두 `192.168.122.2`입니다.
</Note>

### 9.2 DP를 AIO로 초기 구성

AIO VM Console에 접속하여 로그인합니다. 새로 초기화된 Stellar Cyber Appliance의 기본 계정은 `aella` / `changeme`이며, 최초 로그인 시 비밀번호 변경을 요구합니다.

KVM의 고정 Management 주소를 설정하고 AIO 역할을 초기화합니다.

```text
set interface management ip 192.168.122.2/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8

set role AIO
set cluster_name AIO
set cluster_size 1
set cm 192.168.122.2
set otp <YOUR-OTP>

reset
```

<Warning>
`<YOUR-OTP>`에는 실제 배포에 발급된 OTP/License Key를 입력합니다. 실제 OTP를 문서, 스크린샷 또는 Git 저장소에 저장하지 마십시오.
</Warning>

확인 메시지가 표시되면 Reset을 승인합니다. Appliance가 필요한 Platform Image를 다운로드하고 설치합니다.

### 9.3 AIO 초기화 상태 확인

초기화가 진행되거나 완료된 뒤 다음 명령으로 상태를 확인합니다.

```text
show status
```

Stellar Cyber 6.5.x 공식 AIO 초기화 절차에서는 완료 상태의 기준으로 약 **80~90개의 Image가 설치**되고, 모든 Pod가 실행 중이며, 빨간색으로 표시되던 상태 메시지가 정상 Ready 상태로 변경되는 것을 확인하도록 안내합니다.

AIO가 정상/Ready 상태가 되기 전에는 운영 데이터 처리를 시작하지 마십시오.

### 9.4 AIO Data Storage 추가

KVM Installer는 AIO Data Lake용 LV를 AIO VM의 **`vdb`** 장치로 연결합니다.

먼저 Storage 장치를 확인합니다.

```text
show storage
```

예상한 Data Disk가 `vdb`인지 확인한 뒤 Data Lake/Elasticsearch용 Storage로 추가합니다.

```text
add storage blk vdb
```

`vdb`가 실제 Data Lake용 장치인지 확인한 경우에만 Format 경고에서 `Y`를 입력합니다.

완료 후 다시 확인합니다.

```text
show storage
```

<Warning>
`add storage blk` 명령은 선택한 장치를 Format합니다. 확인 전에 장치 이름과 예상 용량을 반드시 검증하십시오.
</Warning>

### 9.5 추가한 Storage로 데이터 마이그레이션

Storage 장치를 추가한 뒤 다음을 수행합니다.

1. AIO Web UI에 로그인합니다.
2. **System → DATA MANAGEMENT → Data Management → Advanced**로 이동합니다.
3. **Migrate to New Directory**에서 **`/es-data-lvm`**을 선택합니다.
4. **Start Migration**을 클릭합니다.
5. 데이터 마이그레이션이 완료될 때까지 기다립니다.
6. **System → DATA MANAGEMENT → Data Lake**로 이동합니다.
7. Node List를 엽니다.
8. **Data Storage Space**에 예상한 용량이 표시되는지 확인합니다.

### 9.6 AIO GUI 접속

AIO VM 자체는 KVM NAT Network에서 `192.168.122.2/24`를 사용합니다. 외부 PC에서는 이 Installer가 구성한 **KVM Host Management IP**를 사용하여 Data Platform Web UI에 접속합니다.

예시:

```text
https://10.10.10.10
```

Stellar Cyber GUI의 초기 계정은 `admin`, 기본 비밀번호는 `changeme`입니다. 운영 환경 사용 전에 기본 비밀번호를 변경하십시오.

### 9.7 Sensor를 AIO에 연결

AIO가 정상 Ready 상태가 된 뒤 KVM Sensor VM을 AIO에 연결합니다.

AIO & Sensor KVM Installer는 Sensor VM을 다음과 같은 고정 NAT 설정으로 배포합니다.

| 설정 | KVM Sensor 값 | 사용자 변경 필요 |
| --- | --- | --- |
| VM 이름 | `mds` | 아니오 |
| Management IP | `192.168.122.3/24` | 아니오 |
| Gateway | `192.168.122.1` | 아니오 |
| DNS | `8.8.8.8` | 아니오 |
| Hostname | 고유한 Sensor Hostname | **예 / 권장** |
| CM Controller | `192.168.122.2` | 아니오 |
| Proxy | 환경별 설정 | 선택 |
| Tenant ID | 환경별 설정 | 선택 |

#### 로그인 및 기본 비밀번호 변경

Sensor Console에 접속하여 초기 계정으로 로그인합니다.

```text
aella / changeme
```

최초 로그인 시 비밀번호 변경을 요구합니다. 비밀번호를 변경하면 Session이 자동으로 종료됩니다. 새 비밀번호로 다시 로그인하면 CLI Prompt가 `DataSensor>`로 변경됩니다.

#### KVM 고정 Management Network 설정

이 KVM Installer는 Sensor에 고정 주소를 사용합니다. 다음과 같이 설정합니다.

```text
set interface management ip 192.168.122.3/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8
```

Interface 설정을 확인합니다.

```text
show interfaces
```

<Note>
Stellar Cyber 공식 Modular Sensor 가이드는 DHCP도 지원하지만, 이 AIO & Sensor KVM Installer는 Sensor를 고정 `192.168.122.3/24` NAT 주소로 배포합니다. 이 토폴로지에서는 위의 Static 설정을 사용하십시오.
</Note>

#### 고유한 Sensor Hostname 설정

Installer가 생성하는 Sensor VM 이름은 `mds`이지만, Stellar Cyber에 표시되는 Sensor Hostname은 여러 Sensor를 운영하는 환경에서 고유하게 설정하는 것을 권장합니다.

예:

```text
set hostname mds-site1
```

Site, 고객 또는 설치 위치를 식별할 수 있는 Naming Rule을 사용하십시오.

#### 선택 사항: HTTP Proxy 설정

Sensor에서 Proxy가 필요한 환경에서만 설정합니다.

```text
set proxy http://<proxy-ip>:<port>
```

#### 선택 사항: Tenant 지정

특정 Tenant에 속하는 Sensor인 경우 다음과 같이 설정합니다.

```text
set tenant_id <TENANT-ID>
```

#### Sensor를 AIO에 연결

이 KVM AIO 토폴로지에서 Stellar Cyber Platform Management Endpoint는 `192.168.122.2`의 AIO VM입니다.

```text
set cm 192.168.122.2
```

연결 상태를 확인합니다.

```text
show cm
```

다음을 확인하십시오.

- **CM Controller**: `192.168.122.2`
- **Status**: **Established**

Status가 Established이면 Sensor CLI를 종료합니다.

```text
quit
```

Sensor는 Stellar Cyber Platform에 자동으로 접속하여 자신을 등록합니다.

### 9.8 NTP 및 Timezone 구성

Stellar Cyber는 Sensor에서 NTP와 올바른 Timezone을 구성할 것을 강력히 권장합니다.

정확한 시간 동기화는 Event Timestamp, Correlation 및 문제 해결에 중요합니다.

지원되는 설정 절차는 [Stellar Cyber NTP 및 Timezone Best Practices](https://docs.stellarcyber.ai/6.5.x/Using/Guides/BestPractices-NTP.htm)를 참고하십시오.

### 9.9 Sensor 승인

Sensor가 CM 연결을 Establish하고 AIO에 등록되면 Stellar Cyber에 새 Sensor가 표시됩니다.

운영 데이터 수집에 사용하기 전에 새 Sensor를 승인해야 합니다. 자세한 절차는 [Stellar Cyber Sensor 승인 문서](https://docs.stellarcyber.ai/6.5.x/Configure/Sensors/Sensor-List-Main.htm#Sensor)를 참고하십시오.

<Warning>
등록은 되었지만 승인되지 않은 Sensor는 정상 운영 준비가 완료된 상태가 아닙니다.
</Warning>



### 9.10 Receiver 및 Sensor Profile 확인

AIO 배포에서는 Receiver가 **DA-Master가 아니라 AIO/DP**를 가리켜야 합니다.

운영 데이터를 보내기 전에 Receiver와 Sensor Profile 설정을 확인하십시오. 이 KVM 토폴로지에서 AIO Guest 주소는 `192.168.122.2`입니다.

`show logforwarder` 명령에 출력이 없다면 먼저 Receiver 설정을 확인하십시오.
