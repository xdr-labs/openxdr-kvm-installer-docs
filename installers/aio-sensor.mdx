# AIO & Sensor KVM Installer User Guide

![AIO & Sensor KVM Installer complete installation flow](/images/AIO-Sensor/1.png)

## Overview

This document is the comprehensive user guide for the **Stellar Cyber OpenXDR AIO & Sensor KVM Installer**.

It explains how to **install, configure, validate, and operate an All-in-One (AIO) OpenXDR appliance and an XDR Sensor virtual machine** on a KVM host running Ubuntu Server 24.04 LTS.

This guide is intended for system engineers and operators who deploy and manage OpenXDR environments on virtualized infrastructure.

It reflects real operational scenarios including:

- initial installation
- partial reconfiguration
- step reruns
- recovery after reboot or interruption

The procedures follow validated installer behavior and are designed to support stable, repeatable, production-oriented deployments.

## 1. System Architecture

### Example Dell R660 Configuration

![Example Dell R660 AIO and Sensor KVM architecture](/images/AIO-Sensor/2.png)

| Component | Example value |
| --- | --- |
| KVM Host | Dell R660 / Ubuntu 24.04 |
| AIO VM | 48 vCPU, 136 GB RAM |
| MDS VM | 44 vCPU, 80 GB RAM |
| Host Access | 1 GbE UTP, local-only `192.168.0.100` |
| Management & Data Link | 1 GbE or 10 GbE |
| Sensor SPAN | PCI Passthrough |
| OS / VM Disk | 1 × 1.92 TB — Ubuntu 24.04, AIO VM, MDS VM |
| Data Lake | 6 × 3.84 TB — for DLm and AIO |

### Architecture Overview

Stellar Cyber OpenXDR Platform is deployed on one physical server using KVM virtualization.

The installer automatically creates and configures:

- Ubuntu 24.04 KVM host
- libvirt / qemu-kvm virtualization layer
- AIO virtual machine (integrated Data Platform + Analyzer)
- Sensor virtual machine(s)
- NAT-based virtual networking
- PCI Passthrough for SPAN traffic
- LVM-based storage for AIO and Sensor workloads
- CPU affinity and kernel-level performance tuning

The installer automates:

- host OS preparation and tuning
- network configuration and conversion
- storage layout creation
- virtual-machine lifecycle management
- performance-critical configuration such as PCI Passthrough and CPU pinning

## 2. Pre-Installation Preparation

### System Requirements

Before running the installer:

- **root privileges are required**

The installer performs low-level operations including:

- network reconfiguration
- kernel and system tuning
- disk and filesystem configuration
- virtual-machine creation and modification

### Documented Operating System

- This guide is based on **Ubuntu Server 24.04 LTS**.
- For legacy Ubuntu/OpenXDR combinations, verify the current source installer and target-release support scope separately.

## 3. Preparation Steps

1. Switch to a root shell.

```bash
sudo -i
```

2. Download the installer into the current directory.

```bash
curl -O https://raw.githubusercontent.com/xdr-labs/OpenXDR-KVM-Installer/main/AIO-Sensor-Installer.sh
```

3. Make it executable.

```bash
chmod +x AIO-Sensor-Installer.sh
```

4. Run the installer.

```bash
./AIO-Sensor-Installer.sh
```

## 4. NIC Preparation and Design Guidance

### Management NIC

The Management NIC is used for:

- remote access to the KVM host
- access to the AIO web interface
- external management traffic

### Sensor Network Mode

- **NAT mode only**
- implemented using the default KVM `virbr0` network
- this design simplifies deployment and reduces operational risk

### SPAN Attachment

- **PCI Passthrough only**
- bridge-based SPAN attachment is not supported
- IOMMU must be enabled in BIOS
- PCI Passthrough provides the highest packet-capture performance for the Sensor workload

### NIC Preparation

Physically connect required NICs before running the installer.

The installer identifies interfaces using **link state**, so connected cables help distinguish NIC roles during selection.

![NAT uplink NIC selection screen](/images/AIO-Sensor/3.png)

## 5. Installer Navigation

The installer provides an interactive menu-driven interface implemented with Whiptail.

### Navigation

- **Spacebar or Down Arrow (↓)**: move through menu items
- **Enter**: select
- **q or ESC**: exit a help screen or return to the previous menu

### State-Aware Execution

The installer is **state-aware**.

Installation state is stored under:

```text
/root/xdr-installer
```

- completed steps are recorded
- after reboot or interruption, execution resumes from the next incomplete step

To clear all installation state and restart from the beginning:

```bash
rm -rf /root/xdr-installer
```

### Mandatory Reboot Steps

The installer automatically reboots after:

- **STEP 03 – network conversion (netplan → ifupdown)**
- **STEP 05 – kernel and system-level tuning**

These reboots are mandatory and must not be skipped.

After reboot:

1. log in again
2. relaunch the installer
3. select Menu 1

The installer resumes automatically.

### Main Menu Overview

#### 1. Auto Execute All Steps

- runs all steps beginning with the next incomplete step
- resumes after reboot from the last completed step
- recommended for:
  - initial installation
  - continuing after reboot

#### 2. Select and Run Specific Step Only

- runs one selected step independently
- recommended for:
  - AIO VM redeployment
  - Sensor VM redeployment
  - network changes
  - image updates
  - SPAN configuration changes

#### 3. Configuration

Configures:

- `DRY_RUN` (default: `1`)
- `AIO_VERSION`
- `SENSOR_VERSION`
- `SENSOR_NET_MODE` (`nat` only)
- `SPAN_ATTACH_MODE` (`pci` only)
- ACPS credentials
  - username
  - password
  - URL

#### 4. Full Configuration Validation

Validates:

- KVM
- AIO VM
- Sensor VM
- networking
- SPAN
- storage

Detailed errors and warnings are displayed.

#### 5. Script Usage Guide

- displays the built-in help guide

#### 6. View Log

- displays the installer log

#### 7. Exit

- exits the installer

## 6. Installation Scenarios

### 6.1 New Installation

This scenario applies immediately after Ubuntu installation.

#### Initial Configuration

From the main menu, select:

```text
3) Configuration
```

![AIO & Sensor Installer Configuration screen](/images/AIO-Sensor/4.png)

Configure:

- `DRY_RUN` (default: `1`)
  - default: `1` (simulation mode)
  - set to `0` only for real installation
- `AIO_VERSION`
- `SENSOR_VERSION`
- ACPS credentials
  - username
  - password
  - URL
- `AUTO_REBOOT` (default: `1`)
- SPAN mode is fixed to `pci`
- network mode is fixed to NAT

Return to the main menu after configuration.

#### Auto Execute

Select:

```text
1) Auto execute all steps
```

![AIO & Sensor Installer Auto Execute All Steps](/images/AIO-Sensor/5.png)

The installer runs:

```text
STEP 01 → STEP 02 → STEP 03 → … → STEP 13
```

Execution stops automatically if a reboot is required or an error occurs.

### Mandatory Reboot Behavior

The host is automatically rebooted after:

- **STEP 03 – network configuration changes**
- **STEP 05 – kernel and system tuning**

After reboot:

1. log in again
2. relaunch the installer
3. select Menu 1

The installer resumes from the next incomplete step.

### 6.2 Run a Specific Step

## 9. After AIO & Sensor Deployment

### 9.1 Default KVM Network Configuration

The KVM AIO deployment uses the local libvirt NAT network with fixed guest addresses:

- AIO IP: `192.168.122.2/24`
- MDS IP: `192.168.122.3/24`
- Gateway: `192.168.122.1`
- DNS: `8.8.8.8`

<Note>
In an AIO deployment, the AIO management IP and the `set cm` address are the same. For this KVM deployment, both use `192.168.122.2`.
</Note>

### 9.2 Configure the DP as an AIO

Open the AIO VM console and log in. On a newly initialized Stellar Cyber appliance, the default login is `aella` / `changeme`, and you are prompted to change the password.

Configure the fixed KVM management address and initialize the AIO role:

```text
set interface management ip 192.168.122.2/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8

set role AIO
set cluster_name AIO
set cluster_size 1
set cm 192.168.122.2
set otp <YOUR-OTP>

reset
```

<Warning>
Replace `<YOUR-OTP>` with the OTP/License Key issued for the deployment. Never store a real OTP in documentation, screenshots, or source control.
</Warning>

Confirm the reset when prompted. The appliance downloads and installs the required platform images.

### 9.3 Verify AIO Initialization

After initialization, verify the appliance:

```text
show status
```

For Stellar Cyber 6.5.x, the official AIO initialization procedure indicates that a completed system should show approximately **80–90 installed images**, all pods running, and status messages changed from red to the normal ready state.

Do not continue to production use until the AIO reports a ready/healthy status.

### 9.4 Add the AIO Data Storage

The KVM Installer attaches the AIO Data Lake LV to the AIO VM as **`vdb`**.

First verify that the device is visible:

```text
show storage
```

Confirm that the expected data disk is `vdb`, then add it for Data Lake/Elasticsearch use:

```text
add storage blk vdb
```

Type `Y` only after verifying that `vdb` is the intended Data Lake device. The selected device is formatted.

Verify storage again:

```text
show storage
```

<Warning>
The `add storage blk` operation formats the selected device. Verify the device name and expected capacity before confirming.
</Warning>

### 9.5 Migrate Data to the Added Storage

After the storage device has been added:

1. Log in to the AIO graphical user interface.
2. Navigate to **System → DATA MANAGEMENT → Data Management → Advanced**.
3. From **Migrate to New Directory**, select **`/es-data-lvm`**.
4. Click **Start Migration**.
5. Wait for the data migration to complete.
6. Navigate to **System → DATA MANAGEMENT → Data Lake**.
7. Open the node list.
8. Verify that **Data Storage Space** shows the expected capacity.

### 9.6 Connect to the AIO GUI

The AIO VM itself uses `192.168.122.2/24` on the KVM NAT network. From an external workstation, use the **KVM host Management IP** as documented by this installer.

Example:

```text
https://10.10.10.10
```

The initial Stellar Cyber GUI account is `admin` with password `changeme`. Change the default password before production use.

### 9.7 Connect the Sensor to the AIO

After the AIO is ready, connect the KVM Sensor VM to the AIO.

The AIO & Sensor KVM Installer deploys the Sensor VM with these fixed NAT settings:

| Setting | KVM Sensor value | Operator change required |
| --- | --- | --- |
| VM name | `mds` | No |
| Management IP | `192.168.122.3/24` | No |
| Gateway | `192.168.122.1` | No |
| DNS | `8.8.8.8` | No |
| Hostname | Unique sensor hostname | **Yes / recommended** |
| CM Controller | `192.168.122.2` | No |
| Proxy | Environment-specific | Optional |
| Tenant ID | Environment-specific | Optional |

#### Log in and change the default password

Open the Sensor console and log in with the initial credentials:

```text
aella / changeme
```

You are prompted to change the password. After the password change, the session closes automatically. Log in again with the new credentials; the CLI prompt changes to `DataSensor>`.

#### Configure the fixed KVM management network

The KVM Installer uses a static address for the Sensor. Configure:

```text
set interface management ip 192.168.122.3/24
set interface management gateway 192.168.122.1
set interface management dns 8.8.8.8
```

Verify the interface configuration:

```text
show interfaces
```

<Note>
The upstream Stellar Cyber Modular Sensor guide supports DHCP, but this AIO & Sensor KVM Installer deploys the Sensor on the fixed `192.168.122.3/24` NAT address. Use the static configuration above for this topology.
</Note>

#### Set a unique Sensor hostname

The Installer creates the Sensor VM as `mds`, but the Sensor hostname shown in Stellar Cyber should be unique in environments with multiple Sensors.

For example:

```text
set hostname mds-site1
```

Choose a naming convention appropriate for the site, customer, or location.

#### Optional: configure an HTTP proxy

Only when the Sensor must use a proxy:

```text
set proxy http://<proxy-ip>:<port>
```

#### Optional: assign a Tenant

If this Sensor belongs to a specific Tenant:

```text
set tenant_id <TENANT-ID>
```

#### Connect the Sensor to the AIO

For this KVM AIO topology, the Stellar Cyber Platform management endpoint is the AIO VM at `192.168.122.2`.

```text
set cm 192.168.122.2
```

Verify the connection:

```text
show cm
```

Confirm that:

- **CM Controller** is `192.168.122.2`
- **Status** is **Established**

When the status is Established, exit the Sensor CLI:

```text
quit
```

The Sensor automatically contacts the Stellar Cyber Platform and registers itself.

### 9.8 Configure NTP and Timezone

Stellar Cyber strongly recommends configuring NTP and the correct timezone on the Sensor.

Accurate time synchronization is important for event timestamps, correlation, and troubleshooting.

Refer to the [Stellar Cyber NTP and Timezone Best Practices](https://docs.stellarcyber.ai/6.5.x/Using/Guides/BestPractices-NTP.htm) for the supported configuration procedure.

### 9.9 Authorize the Sensor

After the Sensor establishes the CM connection and registers with the AIO, it appears in Stellar Cyber.

Authorize the new Sensor before using it for production data collection. Refer to the [Stellar Cyber Sensor authorization documentation](https://docs.stellarcyber.ai/6.5.x/Configure/Sensors/Sensor-List-Main.htm#Sensor).

<Warning>
A Sensor that has registered but has not been authorized is not ready for normal production operation.
</Warning>



### 9.10 Verify the Receiver

For an AIO deployment, the receiver must point to the **AIO/DP**, not to a DA-Master.

Verify the receiver and Sensor Profile before sending production data. In this KVM topology, the AIO guest address is `192.168.122.2`.

If `show logforwarder` returns no output, verify the receiver configuration first.

### 9.11 CLI and SSH Access

Appliance CLI:

```text
console aio
console mds
```

SSH access:

- AIO: **port 2222**
- MDS: **port 2223**
